# 知识库整理

## 核心结果

根据用户已经授予的权限选择模式：

1. **方案模式**：盘点全部语料，提出完整目录、合并/拆分方案和一篇代表性样稿，然后等待审阅。
2. **执行模式**：目录、风格和写入策略已经确认后，先落实目录，再按每批 2–3 篇整理正文；每批回读合格后才进入下一批，最后审计整个范围。

用户已经确认过账号、范围、目录、风格或写入策略后，不要重复询问。无人值守执行时无需逐批等待用户批准，但内部检查点不能跳过。

进入执行模式前必须读取 [批次执行与覆盖台账](references/batch-execution.md) 和 [正文重组与轻度润色](references/body-reorganization.md)；操作飞书/Lark 时还必须读取 [飞书知识库写后审计](references/feishu-kb-audit.md)。

## 不可妥协的完成标准

整理知识库不是给原文套标题。必须同时完成三层工作：

- **目录层**：页面归属、父子层级、命名、合并/拆分关系清楚；
- **正文层**：每篇文档主题明确，相关内容已整合，段落顺序合理，零碎信息得到补全或安置；
- **系统层**：重复内容有唯一主页面，相关页面能互相导航，全部节点都有明确处置状态。

以下情况都不算完成：只改目录、只改标题层级、只做格式化、把原始段落原样搬到新页面、只整理抽样页面却声称全库完成，或只看到写入命令成功而没有回读正文。

> 保留原意不等于原文不动。结构编辑必须让正文的逻辑、完整性和公开可读性发生真实改善，同时不把作者的真实经验改写成另一种声音。

## 强制执行流程

### 1. 全量盘点并建立覆盖台账

递归列出范围内的全部节点。对每个节点记录：原位置、主要主题、目标页面、合并/拆分动作、隐私/时效提示、正文状态和回读结果。

正文状态只能使用以下状态，不能用模糊的“已处理”：

- `未完整阅读`
- `已判断主题与归属`
- `正文整理中`
- `已写回`
- `受阻待恢复`
- `已回读验收`
- `完整阅读后确认无需修改`

只有最后两种状态可以计入完成数。大型知识库可以分批读取，但不得把样本判断冒充全库结论。具体台账和批次门见 [批次执行与覆盖台账](references/batch-execution.md)。

### 2. 编辑前恢复上下文

结合全库材料解释缩写、别名、人物/组织/项目关系，以及“这个问题”“第三点”“上一篇”等指代。无法可靠恢复时标记 `待核验`，不要猜测。

区分材料的知识功能：导览、事实/时间线、概念/方法、工作流、案例/模板、复盘经验、原始资料/归档。不要让原始文件名或记录日期机械决定最终结构。

### 3. 先完成目录，再开始正文

先确认或实施目标目录，包括：

- 每个一级部分服务什么读者任务；
- 每个节点的目标父级与排序；
- 哪些源节点合并、拆分、重命名、保留或归档；
- 重复主题的唯一主页面在哪里；
- 目录中是否仍有孤立、重复、错层或临时命名的节点。

目录没有完成并回读验证前，不要开始大批量正文编辑。若正文整理中发现目录判断确实错误，可以修正，但必须同步更新台账和受影响页面。

### 4. 按每批 2–3 篇整理正文

每批严格执行：

1. 完整读取本批页面及必要的关联页面；
2. 为每篇写内部页面简报：读者问题、核心主题、应保留事实、待合并内容、结构草案；
3. 重组同主题内容，决定段落先后和唯一主页面；
4. 精确编辑正文，补全残句、主谓宾、必要背景和过渡；
5. 写回后重新读取页面，核对标题层级、正文逻辑、关键细节和链接；
6. 本批全部通过后更新台账，再进入下一批。

“正文整理”必须达到的判断标准、原文保留边界和去重方法见 [正文重组与轻度润色](references/body-reorganization.md)。

### 5. 整库收尾审计

所有批次结束后，再递归读取目标目录与页面状态，至少核对：

- 每个原始节点都有保留、移动、合并、拆分、归档或删除的来源处置记录；
- `最终目标页面总数 = 已回读验收数 + 完整阅读后确认无需修改数`；
- 没有仍处于其他状态的页面；
- 目录与正文主题一致，没有遗漏、孤页、重复主页面或空壳页；
- 时间说明、标题层级、敏感信息处理和相关链接符合约定；
- 每篇正文都可被新读者独立理解，没有明显的原始碎片堆积；
- 创建、移动、合并或拆分后的旧节点已经按策略处理。

飞书/Lark 的节点、区块、版本和回读检查见 [飞书知识库写后审计](references/feishu-kb-audit.md)。只要整库审计未通过，就只能报告“部分完成”和剩余清单，不能报告“已经整理完”。

## 合并、拆分与去重

多篇短笔记内容重叠、共同回答一个读者问题时合并；单篇同时包含不同主题、受众、流程或知识类型时拆分。优先建立能独立阅读的页面，并用这个问题判断：

> 三个月以后，读者不记得原项目，还能看懂这个页面吗？

同一事实需要出现在多个任务场景时，指定一个**唯一主页面**保存完整细节；其他页面只保留完成当前任务所需的摘要并链接到主页面。不要复制粘贴整段造成多个版本。

## 保留真实细节和作者表达

除非用户明确要求重写，否则把任务视为“结构重组 + 必要润色”，顺序如下：

1. 按主题移动、合并或拆分；
2. 调整信息顺序和段落关系；
3. 明确页面标题和 H1/H2/H3；
4. 删除完全重复的内容；
5. 修复残句、缺少的主语、明显语病和必要衔接；
6. 只有轻度修改仍无法表达原意时，才重写局部段落。

保留事实、案例、第一人称视角、判断、有辨识度的措辞和有参考价值的具体细节。不要把旅行计划、路线、价格、课表、邮件通知、住宿信息或个人决定抽象成空泛方法论，也不要添加原材料没有支持的正文。

页面主题和读者用途必须清楚，但不要强迫每篇都套统一文章模板。只在新读者缺少必要背景时补简短引言；列表只用于清单、步骤、比较或映射。完整性按材料和页面用途判断，不按字数判断。

面向读者的正文不要出现“原笔记写道”“源材料记录了”“公开版保留了”“整理后可以看到”等编辑过程元话语。来源追溯应放在正文之外。

## 隐私与历史信息

公开分享不等于删除历史细节。区分真实风险与参考价值：

- **必须删除或脱敏**：密码、验证码、恢复密钥、有效令牌、政府证件号、学号、银行信息、URL 中的账号凭据；
- **默认删除，除非用户同意保留**：私人个体完整姓名、仍在使用的个人电话或邮箱、订单号，以及可能带来访问或骚扰风险的信息；
- **无现实风险时保留**：历史房间号、旧住宿或服务电话、公开机构联系方式、注明日期的课表、学校邮件/通知、旅行计划、历史价格和不含秘密的链接；
- **描述性或历史性链接参数可以保留**：只移除有效秘密、认证令牌或仍会暴露身份的标识符。

对真实经历知识库，在相关页面开头添加清晰时间说明。若用户给过固定文案，逐字遵守；否则使用：

> ⚠️ 时间说明：本文记录的是我在 {时间范围} 的经历，仅供参考。具体情况可能发生变化，请以最新官方通知和实际情况为准。

用户明确不要求核验时，不要联网替换旧数值，也不要把每项都标成 `待核验`。保留注明时间的个人经验快照。

只有系统规则要求或用户明确要求核验当前事实时，才进行网络核验；不要因为内容将公开分享就自行刷新历史资料。

## 可追溯与事实边界

内部台账必须记录每个目标页面参考了哪些源节点，但公开正文不暴露整理过程。提出样稿时，把来源说明放在样稿之后或单独映射表中。

始终区分：源材料明确存在的事实、根据多份材料推断的联系、编辑造成的结构调整、需要外部核验的内容。不要把推断写成事实，也不要虚构过渡或结论。

## 方案模式输出

按顺序交付：

1. **语料诊断**：主题重叠、简写、碎片化、公开分享风险与结构问题；
2. **建议目录**：完整目标目录和各部分读者用途；
3. **合并/拆分方案**：使用“来源｜操作｜目标页面｜说明”的映射；
4. **代表性样稿**：选择能检验多来源整合、上下文恢复和目标语气的页面，并在正文外附来源说明；
5. **聚焦审阅问题**：只询问目录颗粒度、样稿风格和主要读者。

样稿必须像已经完成的知识库文章，不能只是对整理过程的评论，也不要为了显得整齐而完全重写作者表达。

**🔴 检查点 · 停止：** 用户未确认目录、样稿风格和写入策略时，不要整理全文。此前已经确认则直接进入执行模式。

## 执行模式报告

报告必须基于覆盖台账与回读证据，而不是工作量印象。至少包括：

- 盘点总数、目录处置数、正文验收数、确认无需修改数、未完成数；
- 创建、合并、拆分、移动、重命名和正文重组的页面；
- 删除或保留敏感/历史信息所依据的规则；
- 无法确认而保留的内容；
- 回读证据与仍未通过的页面清单。

## 执行保护

写入策略未知时，确认：新建整理副本、归档后整理、原地编辑，或只输出不写入。通过修订历史、归档或备份保持可恢复性。账号、目标位置、范围或写入策略变化时，触发新的 **🔴 检查点 · 停止**。

中文长文默认将页面标题与正文标题分开，使用 H1 `一、二、三……`、H2 `1、2、3……`、H3 `(1) (2) (3)……`；用户或生效格式规范另有规定时从其规定。不要跳级，不要为局部编辑覆盖无关正文。

| 触发条件 | 立即处理 | 仍然失败时 |
|---|---|---|
| 无法访问指定账号或来源 | 核对身份、权限、URL/token 和范围 | 报告阻碍；不得切换账号或静默使用不完整语料 |
| 语料过大 | 先全量盘点节点，再分批完整读取 | 标明尚未读取边界；不得把样本冒充全库 |
| 隐私状态不明确 | 保留原文，先删除确定的账号凭据 | 评估组合识别风险后询问用户 |
| 写入冲突或部分成功 | 读取最新状态，区分已完成与未完成区块 | 只重试未完成区块，不覆盖整页 |
| 写入成功但回读不一致 | 保持未完成状态并比较差异 | 精确修复或明确报告，不得宣称完成 |
