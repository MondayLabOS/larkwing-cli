## 适用范围

用于飞书/Lark Wiki 与 Docx 的目录实施、区块编辑和最终验收。具体命令以当前安装的 Lark Skills 与工具帮助为准；不要凭记忆猜命令或字段。

## 操作前

1. 核对用户指定账号/profile；未指定时先确认身份。
2. 解析 Wiki 节点与实际文档 token，确认空间、目标根节点和写入权限。
3. 递归列出目标范围全部节点，记录节点 token、文档 token、类型、父节点、标题和子节点。
4. 对要编辑的文档获取完整正文与区块；长文分段获取直至末尾，不能只读摘要或首屏。
5. 记录每个原始文档的 revision/version、更新时间、区块数量和可用于识别并发修改的状态。
6. 确认目录方案、正文模式、样稿标准和隐私处理；任一项未确认时保持只读。
7. 告知默认 copy-first：原始节点完整保留，整理后页面另外创建；用户明确要求原地修改或删除时重新确认。

目录方案确认阶段不得创建、移动、重命名、合并或拆分真实节点。默认等样稿确认后，先完成原文备份审计，再创建整理后目录；简单移动/重命名也不能绕过备份。

## 原文备份审计

知识库内默认创建 `99 原始文档备份（YYYY-MM-DD）`；名称冲突时生成唯一名称，不覆盖已有备份。优先保留原始节点及其版本：

1. 冻结创建备份前的原始节点清单；
2. 将原始节点移入备份树而不编辑正文，或保持原始树不动并另建整理后根目录；
3. 不把复制出来的新节点当作“原始节点版本未变”的证据；
4. 递归回读备份树，逐一核对原始 node/doc token、标题、父子关系、revision/version、区块数量、正文关键项、表格、图片、附件和链接；
5. 验证所有原始文档 revision/version 未因正文编辑而变化；仅移动 Wiki 父级时单独记录目录变化；
6. 将备份树从整理后目标节点统计、正文批次和内容扫描中排除；
7. 任一原始节点缺失、版本异常或内容不一致时立即停止，不创建整理后页面。

修订历史只能作为额外恢复手段，不能代替可见、可递归核验的原文备份。

## 目录审计

目录操作完成后重新递归列出并比较：

- 目标根节点与范围没有漂移；
- 备份树与整理后目标树边界清楚，备份树未计入目标节点总数；
- 整理后节点总数和处置台账一致；
- 父子关系、顺序和标题正确；
- 合并/拆分产生的新旧节点都有明确状态；
- 不存在重复标题但语义相同的主页面；
- 不存在本应有正文却只有标题的非预期空壳页；
- 索引或导览页中的链接指向实际节点。

目录回读未通过时，不进入正文批量编辑。

## 精确写入

- 优先编辑明确区块，不为调整局部内容覆盖整篇文档；
- 写入前重新读取目标区块，避免基于旧版本覆盖用户新改动；
- 把内容写入、合并或拆分到新页面时保留表格、列表、引用、附件、图片说明和链接；
- 页面标题与正文标题分开处理；
- 统一 H1/H2/H3 时检查是否跳级，不能把正文误转成标题；
- API 返回成功只表示请求被接受，不能代表内容正确；
- 所有写入目标都是备份树之外的新文档区块；
- 保留原文模式只执行编辑契约允许的结构、格式、标点和明显错别字修正；
- 整理优化模式先记录必须保留信息，再进行去重或改写。

## 单篇回读

每次写入后重新获取完整页面，先核对：

1. 对应旧文档仍在备份树或原始源树，revision/version 与冻结清单一致；
2. 写入目标是整理后新页面，不是旧文档；
3. 页面标题、正文主标题和章节层级；
4. 页面主题、目录归属和段落顺序；
5. 表格行列、列表嵌套、引用、图片、附件和超链接是否仍存在；
6. 时间说明与隐私处理是否符合编辑契约；
7. 是否凭空补充事实或遗留编辑过程元话语；
8. 版本/更新时间是否对应本次新页面写入，且无未处理并发变化。

再按正文模式核对：

**保留原文**

- 全部源区块都能在最终页面或明确的原始资料区找到；
- 除有记录的标题、格式、标点和明显错别字修正外，原文没有变化；
- 重复、残句、孤立链接或无说明清单没有被静默删除；
- 姓名、电话、邮箱、地址等隐私没有被未经授权地脱敏；
- 密码、验证码、有效令牌、恢复密钥或访问凭据没有被继续复制或公开。

**整理优化**

- 要求保留的价格、时间、路线、通知、课表、房间/电话、链接、案例、判断和第一人称细节仍在；
- 重复内容、残句、无说明清单和孤立链接按样稿标准处理；
- 没有删除独有信息，也没有泛化成空洞方法论；
- 结果与已确认样稿一致。

需要检查“空内容”时区分真正的空壳区块与飞书表格单元格中的结构性空段落，后者不应误报为正文缺失。

## 整库审计

正文批次全部结束后再次递归读取目录，并从台账抽取每篇最终状态。至少生成以下数字：

```text
范围内节点总数
原始节点总数
原位保留且核验通过
移入备份且核验通过
原始节点异常
原文备份位置
最终目标页面总数
正文模式
已回读验收
完整阅读后确认无需修改
受阻待恢复
未完成
新建 / 重命名 / 合并 / 拆分
原地修改 / 删除旧文档的授权例外
```

对每个未完成节点给出 token/标题、当前状态、失败原因和下一步。不要用“其余同理”“剩下都已处理”代替逐节点状态。

可做全库一致性扫描：

- 标题编号和层级是否统一；
- 必需时间说明是否缺失或重复；
- 目录链接、跨页链接是否失效；
- 是否存在标题空壳、临时标题或未处置源页；
- 原始节点 revision/version 是否全部保持不变；
- 备份树是否被误计入目标页或再次编辑；
- 是否出现明确的隐私或有效凭据候选；
- 是否存在编辑过程元话语；
- 保留原文模式是否发生缺失、未授权改写或静默去重；
- 整理优化模式是否仍有大量短碎句、孤立 URL、重复全文或遗漏独有信息。

自动扫描只能发现候选，不能代替逐篇语义验收。

## 失败与恢复

| 情况 | 状态处理 | 恢复方式 |
|---|---|---|
| 限流或暂时错误 | 保持原状态，不计完成 | 记录失败页，退避后仅重试该页 |
| 部分区块写入成功 | 标记 `已写回` | 获取最新页面，比较并修复缺失区块 |
| 回读与预期不同 | 不得标记验收 | 精确定位标题、正文、链接或媒体差异 |
| 发现用户并发修改 | 暂停该页 | 基于最新版本重新合并，不覆盖用户内容 |
| 权限或账号不符 | 停止整个写入批次 | 核对 profile 和授权，不能切换账号绕过 |
| 无法获取完整正文 | 保持 `未完整阅读` | 修复分页/权限/工具问题后再继续 |
| 发现有效凭据 | 停止该页及相关公开写入 | 列出风险并向用户确认删除、脱敏或保留原位 |
| 原文备份缺失或版本异常 | 停止全部目标写入 | 恢复缺失原文并重新完成整树备份审计 |

只有旧文档保全、目标页回读、正文模式和台账都一致，页面才能从 `已写回` 进入 `已回读验收`。
