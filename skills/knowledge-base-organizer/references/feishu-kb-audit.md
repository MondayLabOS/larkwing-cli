# 飞书知识库写后审计

## 适用范围

用于飞书/Lark Wiki 与 Docx 的目录实施、区块编辑和最终验收。具体命令以当前安装的 Lark Skills 与工具帮助为准；不要凭记忆猜命令或字段。

## 操作前

1. 核对用户指定账号/profile；未指定时先确认身份。
2. 解析 Wiki 节点与实际文档 token，确认空间、目标根节点和写入权限。
3. 递归列出目标范围全部节点，记录节点 token、文档 token、类型、父节点、标题和子节点。
4. 对要编辑的文档获取完整正文与区块；长文分段获取直至末尾，不能只读摘要或首屏。
5. 记录当前版本、更新时间或可用于识别并发修改的状态。

## 目录审计

目录操作完成后重新递归列出并比较：

- 目标根节点与范围没有漂移；
- 节点总数和处置台账一致；
- 父子关系、顺序和标题正确；
- 合并/拆分产生的新旧节点都有明确状态；
- 不存在重复标题但语义相同的主页面；
- 不存在本应有正文却只有标题的空壳页；
- 索引或导览页中的链接指向实际节点。

目录回读未通过时，不进入正文批量编辑。

## 精确写入

- 优先编辑明确区块，不为调整局部内容覆盖整篇文档；
- 写入前重新读取目标区块，避免基于旧版本覆盖用户新改动；
- 移动、合并或拆分内容时保留表格、列表、引用、附件、图片说明和链接；
- 页面标题与正文标题分开处理；
- 统一 H1/H2/H3 时检查是否跳级，不能把正文误转成标题；
- API 返回成功只表示请求被接受，不能代表内容正确。

## 单篇回读

每次写入后重新获取完整页面，核对：

1. 页面标题、正文主标题和章节层级；
2. 页面简报中的核心主题与段落顺序；
3. 要求保留的价格、时间、路线、通知、课表、房间/电话、链接和第一人称细节；
4. 应删除的密码、令牌、学号、证件号和其他敏感信息；
5. 表格行列、列表嵌套、引用、图片、附件和超链接是否仍存在；
6. 时间说明是否出现在需要的页面，文案是否符合用户指定版本；
7. 是否遗留明显残句、无说明清单、重复段落、编辑过程元话语或临时占位；
8. 版本/更新时间是否对应本次写入，且无未处理并发变化。

需要检查“空内容”时区分真正的空壳区块与飞书表格单元格中的结构性空段落，后者不应误报为正文缺失。

## 整库审计

正文批次全部结束后再次递归读取目录，并从台账抽取每篇最终状态。至少生成以下数字：

```text
范围内节点总数
原始节点已处置 / 未处置
最终目标页面总数
已回读验收
完整阅读后确认无需修改
受阻待恢复
未完成
创建 / 移动 / 重命名 / 合并 / 拆分 / 归档 / 删除
```

对每个未完成节点给出 token/标题、当前状态、失败原因和下一步。不要用“其余同理”“剩下都已处理”代替逐节点状态。

可做全库一致性扫描：

- 标题编号和层级是否统一；
- 必需时间说明是否缺失或重复；
- 目录链接、跨页链接是否失效；
- 同一详情是否在多个页面全文重复；
- 是否存在标题空壳、临时标题或未处置源页；
- 是否出现明确敏感信息候选；
- 是否仍有大量短碎句、孤立 URL 或编辑过程元话语。

自动扫描只能发现候选，不能代替逐篇语义验收。

## 失败与恢复

| 情况 | 状态处理 | 恢复方式 |
|---|---|---|
| 限流或暂时错误 | 保持原状态，不计完成 | 记录失败页，退避后仅重试该页 |
| 部分区块写入成功 | 标记 `已写回` | 获取最新页面，比较并修复缺失区块 |
| 回读与预期不同 | 不得标记验收 | 精确定位标题、正文、链接或媒体差异 |
| 发现用户并发修改 | 暂停该页 | 基于最新版本重新合并，不覆盖用户内容 |
| 权限或账号不符 | 停止整个写入批次 | 核对 profile 和授权，不能切换账号绕过 |
| 无法获取完整正文 | 保持 `未完整阅读` | 修复分页/权限/工具问题后再继续 |

只有回读内容和台账都一致，页面才能从 `已写回` 进入 `已回读验收`。
