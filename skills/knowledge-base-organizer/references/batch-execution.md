# 批次执行与覆盖台账

## 目的

用可审计的状态机代替“看起来整理过”。目录先行，正文每批 2–3 篇，批次验收后再前进；用户允许无人值守时，检查点由代理内部执行，不需要反复打断用户。

## 覆盖台账

为范围内每个节点建立一行记录。至少包含：

| 字段 | 说明 |
|---|---|
| 节点 ID / 路径 | 稳定定位原页面 |
| 原标题与父级 | 记录整理前位置 |
| 主要主题 | 用一句话描述页面回答的问题 |
| 目标页面与父级 | 目录调整后的唯一归属 |
| 处置动作 | 保留、重命名、移动、合并、拆分、归档或删除 |
| 关联页面 | 合并来源、拆分目标、重复内容或必要上下文 |
| 风险提示 | 隐私、时效、待核验、外链或附件 |
| 正文状态 | 只能使用主 Skill 定义的状态 |
| 回读证据 | 版本、更新时间、关键标题、关键事实或校验结果 |
| 备注 | 无需修改理由、失败原因或下一步 |

不要把父目录、索引页或短页面排除在台账之外。删除/归档的源节点也必须留处置记录，避免“消失即完成”。

## 阶段 A：目录批次

1. 递归列出全部节点、父子关系、节点类型和标题。
2. 对每个节点至少读取足以判断主题与归属的内容；重复、含混或混合主题页面要完整读取。
3. 形成目标目录和逐节点映射。
4. 实施创建、移动、重命名、合并占位和排序。
5. 重新递归读取目录，核对节点数量、父子关系、标题和顺序。
6. 目录审计通过后，正文状态从 `未完整阅读` 推进到 `已判断主题与归属`。

目录阶段不能用“先改几篇正文看看”替代。目录不稳定会导致同一正文被重复编辑或放入错误主页面。

## 阶段 B：正文批次

### 选择批次

- 默认每批 2–3 篇目标页面；确认范围本来只有 1 篇，或最后只剩 1 篇时直接处理，不等待凑批；
- 优先把同一主题、互相引用或存在重复内容的页面放在同一批；
- 超长页面可以单独成批，但仍需执行完整检查点；
- 不要用“一个大章节”作为模糊批次，必须列出具体页面。

### 批次开始门

开始前确认：

- 页面在已确认目录中；
- 本批所有来源、目标页和关联页都已定位；
- 当前版本已重新读取，未基于过期缓存编辑；
- 本批隐私、时间说明和格式规则明确。

### 批次编辑门

对每篇执行：

1. 完整读取正文、表格、列表、引用、附件说明和链接；
2. 写内部页面简报；
3. 确定与同批/其他页面的内容归属；
4. 更新为 `正文整理中`；
5. 进行结构重组和必要润色；
6. 写入成功后更新为 `已写回`，不能直接标为完成。

### 批次验收门

重新读取写后页面，并逐项核对：

- 页面主题与标题一致；
- 开头提供必要背景，段落顺序能被新读者理解；
- 相同内容已整合，重复信息有唯一主页面；
- 碎片、残句、孤立链接和无说明清单已经处理；
- 原意、真实细节和第一人称视角仍在；
- 标题层级、时间说明、链接、表格和附件未被误伤；
- 没有凭空补充事实或暴露整理过程。

全部通过才标记 `已回读验收`。任一项失败，留在 `正文整理中` 或 `已写回`，精确修复后重新回读。

### 批次结束门

- 本批每篇均为 `已回读验收` 或 `完整阅读后确认无需修改`；
- 台账记录完整；
- 因合并/拆分影响的其他页面已加入后续批次；
- 没有新产生的孤页、重复页或目录冲突。

由正文质量或回读差异导致未通过时，不得移到下一批。若是限流、权限或其他独立的外部阻碍，可以把该页标为 `受阻待恢复` 并继续不依赖它的批次；最终审计前必须返回处理，不能把受阻页标为完成。

## 无需修改分支

只有在完整阅读之后，同时满足以下条件才允许使用：

- 主题单一且标题准确；
- 上下文充分，正文逻辑和段落顺序清楚；
- 没有需整合的重复内容、残句或读者障碍；
- 格式、隐私和时间说明符合全库约定；
- 与其他页面的归属和链接正确。

台账必须写明具体理由，例如“完整阅读 6 个区块，主题单一，无重复或残句，标题层级与时间说明均符合约定”。“内容很短”“看起来还行”不是理由。

## 最终覆盖计算

收尾时分别核对来源处置与目标页面完成度。

每个原始节点都必须有保留、移动、合并、拆分、归档或删除记录；不能因内容已经合并到别处，就从统计中消失。

最终页面计算：

```text
最终目标页面总数
= 已回读验收数
+ 完整阅读后确认无需修改数
```

另列创建页、合并/拆分后的旧页、归档页和删除页，验证目标页面能回溯到来源映射。只要来源节点缺少处置、等式不成立、存在其他状态，或目录回读与台账不一致，就报告部分完成。

## 反偷懒红线

- 不以目录漂亮代替正文整理；
- 不以标题层级统一代替逻辑重组；
- 不以“保留原文”为理由保留明显碎片；
- 不只整理代表性页面或容易页面；
- 不把源笔记堆进一个长页面就称为合并；
- 不在未完整读取时使用“无需修改”；
- 不因写入 API 返回成功就跳过回读；
- 不在部分完成时使用“全部完成”“剩余内容已整理完”。
