## 目的

用可审计的状态机代替“看起来整理过”。先在只读阶段确认目录、正文模式和样稿，再完整保留旧文档、创建整理后目录；目录回读通过后，只对新页面按每批 2–3 篇整理和验收。用户允许无人值守时，检查点由代理内部执行，不需要反复打断用户。

## 覆盖台账

为范围内每个节点建立一行记录。至少包含：

| 字段 | 说明 |
|---|---|
| 节点 ID / 路径 | 稳定定位原页面 |
| 原标题与父级 | 记录整理前位置 |
| 备份位置 | 旧文档在备份树或保持不动的源路径 |
| 原文核验 | 节点/文件数量、版本或哈希、正文和媒体回读结果 |
| 主要主题 | 用一句话描述页面回答的问题 |
| 目标页面与父级 | 目录调整后的唯一归属 |
| 源节点处置 | 默认只用 `原位保留` 或 `移入备份`；其他动作需明确授权 |
| 目标页面动作 | 新建、重命名、合并、拆分或无需创建 |
| 关联页面 | 合并来源、拆分目标、重复内容或必要上下文 |
| 正文模式 | `保留原文` 或 `整理优化` |
| 编辑契约 | 允许删除、改写、隐私处理和样稿约定 |
| 风险提示 | 隐私、有效凭据、时效、待核验、外链或附件 |
| 正文状态 | 只能使用主 Skill 定义的状态 |
| 回读证据 | 版本、更新时间、关键标题、关键事实或校验结果 |
| 备注 | 无需修改理由、失败原因或下一步 |

不要把父目录、索引页或短页面排除在台账之外。默认禁止删除、覆盖或原地改写源节点；用户明确授权例外时也必须留处置记录，避免“消失即完成”。

## 阶段 A：目录方案确认

这一阶段只读，不修改知识库：

1. 递归列出全部节点、父子关系、节点类型和标题；
2. 对每个节点至少读取足以判断主题与归属的内容；重复、含混或混合主题页面要完整读取；
3. 形成完整目标目录和逐节点映射；
4. 在对话中交付现状诊断、建议目录、拆分整合方案和少量待确认问题；
5. 等待用户确认目录，不提供样稿，不创建、移动或重命名实际节点。

目录确认后继续确认正文模式并制作样稿。样稿未确认时，不进入原始文档备份和目录落地。

## 阶段 B：原始文档备份与目录落地

开始前确认：

- 目录方案已确认；
- 正文模式与编辑契约已确认；
- 代表性样稿已确认；
- 账号、目标范围和隐私处理已确认；
- 当前源版本已重新读取，原始节点/文件清单已经冻结；
- 已告知默认 copy-first 与备份位置；用户没有明确要求原地修改或删除旧文档。

随后执行：

1. 记录全部原始节点/文件的稳定 ID 或路径、标题、父级、版本/哈希、正文状态、媒体、附件和链接；
2. 知识库内默认建立 `99 原始文档备份（YYYY-MM-DD）`；名称冲突时使用唯一名称，不覆盖已有备份；
3. 把原始节点移入备份树但不编辑正文，或保持原始源树不动并在旁边新建整理后目录；本地文件默认保持源目录不动并使用独立输出目录；
4. 递归回读备份，核对原始数量、层级、正文、媒体、附件、链接和版本/哈希；任一项不一致时停止；
5. 将备份树标记为只读来源，从目标页面数量、正文批次和后续自动扫描中排除；
6. 在备份树之外创建整理后的新目录、新页面、合并占位和排序，不复用旧文档作为编辑目标；
7. 递归读取整理后目录，核对目标节点数量、父子关系、标题、顺序和来源映射；
8. 检查新建页面是否出现非预期空壳，索引链接是否有效；
9. 原文备份与目标目录审计均通过后，把新页面推进到 `已判断主题与归属`。

默认不在目录方案刚确认时立刻落地，也不以修订历史替代独立旧文档保留。用户明确要求提前实施简单目录变化时，仍必须先完成原文备份和回读。

原文备份或目标目录任一回读未通过时，不进入正文批次。备份不完整会造成不可逆的信息丢失；目标目录不稳定会导致同一正文被重复编辑或放入错误主页面。

## 阶段 C：正文批次

### 选择批次

- 默认每批 2–3 篇目标页面；确认范围只有 1 篇，或最后只剩 1 篇时直接处理，不等待凑批；
- 优先把同一主题、互相引用或存在重复内容的页面放在同一批；
- 超长页面可以单独成批，但仍需执行完整检查点；
- 不要用“一个大章节”作为模糊批次，必须列出具体页面。

### 批次开始门

开始前确认：

- 页面位于已回读通过的目录中；
- 本批写入目标全部是新建整理后页面，不是备份中的旧文档；
- 本批所有来源、目标页和关联页已定位；
- 当前版本已重新读取，未基于过期缓存编辑；
- 正文模式、编辑契约、隐私规则、时间说明和格式规则明确；
- 如果正文模式是保留原文，已建立源区块到目标位置的保全映射；
- 如果正文模式是整理优化，已列出每篇必须保留的独有信息。

### 批次编辑门

每篇先从只读旧文档完整读取正文、表格、列表、引用、附件说明和链接，写内部页面简报，确定与其他页面的内容归属，并把对应的新目标页面更新为 `正文整理中`。

按模式编辑：

**保留原文**

1. 把原文区块复制到新目标页，调整目标页面归属和段落顺序；
2. 添加或调整标题层级、导航、空行、列表等结构；
3. 只修正意思唯一的明显错别字和标点；
4. 记录修正项，不删除、概括、改写或静默去重；
5. 重复内容需要移动时，保留在目标页或明确的原始资料区。

**整理优化**

1. 按主题重组信息，确定唯一主页面；
2. 删除完全重复、口头重复和无信息量占位；
3. 补全残句、必要背景和衔接；
4. 在必须保留信息完整、事实和语气不变的前提下改写句子或段落；
5. 不添加源材料没有的事实、结论或“标准答案”。

写入成功后更新为 `已写回`，不能直接标为完成。

### 批次验收门

重新读取写后页面，先检查两种模式共有的项目：

- 页面主题与目录归属一致；
- 标题层级、链接、表格、列表、引用、图片、附件未被误伤；
- 时间说明和隐私处理符合编辑契约；
- 没有凭空补充事实或暴露整理过程；
- 版本/更新时间与本次写入一致，没有未处理的并发修改。

再按模式验收：

**保留原文**

- 每段源内容都能在目标页或原始资料区找到；
- 除记录过的错别字、标点和格式修正外，原文表达没有变化；
- 没有静默删除重复、残句、孤立链接或无说明清单；
- 隐私信息没有发生未经授权的脱敏；
- 有效凭据没有被继续复制或公开。

**整理优化**

- 开头提供必要背景，内容顺序能被新读者理解；
- 相同内容已整合，重复信息有唯一主页面；
- 碎片、残句、孤立链接和无说明清单已经处理；
- 必须保留的独有事实、真实细节、判断、语气和第一人称仍在；
- 页面没有被泛化成空洞方法论；
- 结果符合已确认样稿。

全部通过才标记 `已回读验收`。任一项失败，留在 `正文整理中` 或 `已写回`，精确修复后重新回读。

### 批次结束门

- 本批每篇均为 `已回读验收` 或 `完整阅读后确认无需修改`；
- 台账与修正记录完整；
- 因合并/拆分影响的其他页面已加入后续批次；
- 没有新产生的孤页、目录冲突或未处置源页。

由正文质量或回读差异导致未通过时，不得移到下一批。若是限流、权限或其他独立外部阻碍，可以把该页标为 `受阻待恢复` 并继续不依赖它的批次；最终审计前必须返回处理，不能把受阻页标为完成。

## 无需修改分支

只有完整阅读后才能使用，并按正文模式判断：

**保留原文**：目录与归属正确，结构和格式已符合约定，原文内容完整，隐私提示已完成，没有需要执行的标题、标点或明显错别字修正。

**整理优化**：主题单一且标题准确，上下文和顺序清楚，没有需整合的重复、残句或读者障碍，格式、隐私、时间说明和相关链接符合约定。

台账必须写明具体理由。“内容很短”“看起来还行”不是理由。

## 最终覆盖计算

收尾时分别核对旧文档保全与目标页面完成度。每个原始节点都必须有 `原位保留` 或 `移入备份` 记录；只有用户明确授权的例外才能记录原地修改或删除。源节点不能因内容已经进入新页面，就从统计中消失。

```text
原始节点总数
= 原位保留且核验通过数
+ 移入备份且核验通过数
+ 用户明确授权的例外数
```

```text
最终目标页面总数
= 已回读验收数
+ 完整阅读后确认无需修改数
```

备份树不计入最终目标页面总数。另列新建页、目标页合并/拆分、备份位置和任何授权例外，验证每个目标页面能回溯到只读来源。保留原文模式还要核对全部源内容均有去向；整理优化模式还要核对全部独有信息均被保留。只要旧文档保全等式或目标页面等式不成立、存在其他状态，或目录回读与台账不一致，就报告部分完成。

## 反偷懒红线

- 不以目录漂亮代替已确认模式下的正文验收；
- 不在原始文档备份完整回读前创建或编辑目标页面；
- 不用修订历史代替独立备份，不编辑备份树中的旧文档；
- 不把备份树再次纳入目标页面统计或正文批次；
- 不在用户未明确授权时删除、覆盖或原地改写旧文档；
- 不只整理代表性页面或容易页面；
- 不在未完整读取时使用“无需修改”；
- 不因写入 API 返回成功就跳过回读；
- 不在部分完成时使用“全部完成”“剩余内容已整理完”；
- 不用整理优化模式擅自删除独有信息；
- 不用保留原文模式偷偷改写，也不因页面仍有碎片就否定用户选择的保全目标；
- 不把两种模式的验收标准混用。
