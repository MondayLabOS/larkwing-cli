# 个人信息记忆

把用户明确要求保存的稳定事实和偏好转成范围清楚、可验证、可更正、可删除的记忆记录，并在后续相关任务中准确复用。

## 操作流程

### 1. 确定操作与授权

识别用户要进行的操作：

- **新增**：记住新的个人信息、偏好、称呼或别名；
- **更正**：用新的明确说明替换旧记录；
- **忘记**：删除指定记录或停止在指定范围内使用；
- **读取**：查询已保存内容，或要求结合历史偏好继续工作。

只有用户明确要求保存、更正或删除时才执行持久化写入。用户只是在当前任务中提到一个事实时，可以在当前上下文使用，但不要自动保存。

先读取当前运行环境提供的记忆规则、存储位置和写入方式。平台规则优先于本 Skill；不得绕过只读文件、受保护索引、授权门或指定的更新入口。没有可写记忆机制时，输出一条可复制的候选记录，并明确说明尚未持久化。

### 2. 判断是否适合长期记忆

优先记录未来多次协作仍可能有用的信息：

- 用户希望使用的姓名、称呼、代词、语言和时区；
- 稳定的沟通、格式、工具或交付偏好；
- 长期角色、职责边界和持续项目中的命名约定；
- 用户明确要求跨任务沿用的项目别名、术语映射或工作习惯。

默认不记录：

- 当前任务的进度、一次性截止时间、临时草稿和短期上下文；
- 从行为、语气或第三方材料推断出的身份、偏好或关系；
- 密码、验证码、API key、访问令牌、恢复密钥、私钥和会话凭据；
- 与未来协作无关的完整证件号、银行卡号、精确住址等高风险个人数据。

用户要求保存高风险信息时，说明风险并拒绝保存秘密；如仍有实际需要，只保留不敏感的替代描述，例如“用户使用公司 SSO”，不要记录凭据本身。

### 3. 写成最小记录

在写入前读取 [记忆记录模板](references/memory-record-template.md)。每条记录至少明确：

- **内容**：用户确认的事实、偏好或映射；
- **范围**：全局、某个项目、某类任务或指定时间段；
- **复用规则**：未来在什么条件下应用；
- **边界**：不能从该记录进一步推断什么；
- **状态**：有效、已更正或待删除。

使用用户原话中最短且无歧义的表达。保留必要的展开形式以便消歧，但不要连带保存无关对话、整段原文或未确认背景。

### 4. 处理冲突与更正

搜索同一主题和相邻关键词的已有记录，再决定新增或更新：

- 新的明确指示与旧记录冲突时，以最新明确指示为准；
- 能精确更新时不要再新增一条重复记录；
- 平台要求保留历史时，将旧记录标为已被新记录取代；否则按平台机制删除或覆盖；
- 范围不同的记录可以并存，例如“全局用中文”和“英文论文任务用英文”；应用时选择最具体的有效范围；
- 无法判断用户是在补充还是替换时，只询问这一处关键差异，不要猜测。

### 5. 写入并验证

仅通过平台允许的记忆工具或更新入口写入。写入完成后立即重新搜索或读取目标记录，核对：

1. 记录内容与用户指示一致；
2. 作用域和复用条件没有被扩大；
3. 旧冲突记录已更新、取代或删除；
4. 没有写入秘密或无关个人信息。

无法回读验证时，不要声称“已经记住”；应报告已提交的动作和仍缺少的验证。

### 6. 应用记忆

在当前及未来相关任务中自然应用有效记录，不必反复提醒用户记忆的存在。只在以下情况主动说明：

- 用户询问你记得什么或为何这样称呼；
- 记录可能已过时、作用域不确定或与当前指示冲突；
- 用户要求更正、删除或导出记录；
- 平台要求披露记忆来源或未验证状态。

不要把称呼偏好当作身份事实，不要把项目别名当作项目进度证据，也不要把一次格式选择推广到所有任务。

## 完成标准

只有同时满足以下条件，才报告记忆操作完成：

- 写操作有明确用户授权；
- 记录内容最小、范围明确且不含秘密；
- 已检查相关旧记录和冲突；
- 已通过平台允许的方式写入；
- 已回读验证，或明确报告无法验证。
